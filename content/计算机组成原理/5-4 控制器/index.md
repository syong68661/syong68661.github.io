## 1. 本质
在正确时序发出正确控制信号,实现基本操作序列.
1. 控制器架构:
	包括单周期处理器/多周期处理器/流水线处理器.
	明白指令是如何执行的,涉及哪些控制信号.
2. 微程序控制与微指令编码:
	根据微指令字段写二进制微程序.
	根据控制字段,转移字段,下地址字段求控存容量.


## 2. 结构/组成
### 单周期处理器-基于组合逻辑
![](<Pasted image 20260829144625.png>)
1. 该模型中共有32个通用寄存器,所以只需要==5位==就可以编码识别出对应寄存器.
#### 指令
共有六条指令集.
![](<Pasted image 20260829144940.png>)
![](<Pasted image 20260829145309.png>)

#### 寻址方式
由于采用定长32位指令字结构,按字节编址.有==寄存器寻址和立即寻址两种方式==.
![](<Pasted image 20260829145232.png>)
#### 核心控制信号
1. ExtOp:0零扩展，1符号扩展
2. ALUSrc:0寄存器输入，1立即数输入
3. ALUctr:控制ALU运算类型
4. nPC_sel:0顺序执行，1分支跳转
5. MemWrite：存储器写使能
6. MemtoReg:0结果来自ALU，1结果来自存储器
7. RegDst:0写rt，1写rd
8. RegWrite：寄存器写使能
#### 特点
1. 由于要求一个时钟周期内完成一条指令,所以==不允许部件服用==.
2. 当一个功能复杂的指令需要多个时钟才可以完成,那么单周期CPU无法满足该功能.如乘法计算:需要多次累加移位操作.
![](<Pasted image 20260829145754.png>)
3. 时钟周期由最慢指令决定,时间利用率低.
### 多周期CPU-基于组合逻辑
#### 五阶段
1. 划分为五个阶段,即取值,译码,执行,访存,写回:
	IF:取指令
	ID:指令译码+读操作数
	EX:执行运算/计算地址
	MEM:存储器读写
	WB:结果写回寄存器
2. 为了使功能块之间不干扰,在==每步都设置存储元件==.即就是在单周期数据通路中,对其切分:
![](<Pasted image 20260829150434.png>)
---
1. 指令寄存器IR:保证指令周期结束之前，当前执行的指令保存在IR中，不会被改变.
2. 操作数寄存器A与B:保证从暂存寄存器堆中取出的内容.
3. ALUOut:暂存ALU的计算结果.
4. 数据寄存器:保证各个段之间都有效分割.
---

#### 公共阶段
1. IF
![](<Pasted image 20260829151217.png>)
数据通路描述：PC的内容送入指令存储器的地址端，取出的指令写入指令寄存器IR;同时PC送入“下一个PC计算”部件，生成PC+4，并写回PC。
B8420控制信号：IRWr=1，PCWr=1，nPC_sel=0，RegWrite=0，MemWrite=0.
2. ID
![](<Pasted image 20260829151535.png>)
数据通路描述:IR中的rs字段送入寄存器堆RA端，读出`R[rs]`并暂存到A;IR中的rt字段送入寄存器堆RB端，读出`R[rt]`并暂存到B。控制器根据IR中的操作码判断后续进入哪类执行路径。
控制信号：IRWr=0，PCWr=0，RegWrite=0，MemWrite=0.
#### 以ADD指令的后续阶段
3. EX
![](<Pasted image 20260829151852.png>)
控制信号：M3=0(选择B)，ALUctr=00，RegWrite=0，MemWrite=0.
4. WB
![](<Pasted image 20260829152001.png>)
控制信号:M1=1(选择rd)，M2=0(选择ALUout)，RegWrite=1，MemWrite=0.
### 微程序控制器-基于存储逻辑
1. 控制器发出==微命令==,对应==一个微操作==.
2. ==一个微程序==对应==一个机器指令==.
![](<Pasted image 20260829152832.png>)
---
1. 起始和转移地址形成部件:用来产生初始和后继地址.
2. 微程序计数器uPC :接受为地址,为读取微指令做准备.
3. 控制存储器CS/CM:存放各个指令对应的微程序.
4. 微指令寄存器uIR:位数等于微指令字长.

#### 工作过程
其中取指,间址,和中断周期等,属于公共阶段,即==每个指令在这些阶段,对应的微指令是一样的==,从而==可以共用==.
1. 取指:
	IR寄存器为空.机器开始运行时,自动将微程序的入口地址送入uPC,并从CM中读取对应微指令送入uIR.
![](<Pasted image 20260829153618.png>)
2. 取到对应指令,会根据指令的操作码字段,形成对应微程序的入口地址,从而开始执行该指令.
![](<Pasted image 20260829153819.png>)
#### 基本概念
1. 微指令组成:
	操作控制字段:用于产生各种操作控制信号.
	顺序控制字段:用于产生下一条微指令地址.
2. 微周期:
	取出并执行一条微指令所用的时间.
3. 主存:
	用于存放程序和数据,放在CPU外部,用RAM和ROM实现.
4. 控制存储器CM:
	存放微程序,在CPU内部,用ROM实现.
5. 微命令和微操作不是微程序控制器专属,但==微指令==是微程序控制器专属.
#### 微指令编码方式
1. 直接编码:
	不用进行译码.
	编码效率低,且对容量有大需求.
2. 字段直接编码:
	将控制字段分成若干字段,可以同时发出好几个指令.==缩短了指令字长==.
	==因此将互斥微命令放在一个字段中==.
	同时每个小段要留出==一个状态==.
3. 字段间接编码
4. 最短编码.
#### 微地址形成方式
1. 增量方式
2. 断定法(下地址法)
	加快了指令执行速度,但增加了指令长度.
#### 微指令格式
1. 水平型:直接编码,字段直接编码,字段间接编码都是属于.
	==并行能力强,执行速度块.==但是编写麻烦(指令比较长).
![](<Pasted image 20260829155114.png>)

2. 垂直型:在微指令字中设置微操作码字段,==通常只能定义并执行一种微命令==.
	==指令短,执行速度慢==.
