## 2. 结构/组成
### cache结构
1. SRAM
	放在CPU芯片内，速度与CPU几乎一样快。
	多级Cache，部分在CPU内部，部分在CPU和主存之间。
	分为==指令cache和数据cache==。
2. 地址映射表和数据区
![](<Pasted image 20260825163935.png>)
	注意算==cache总容量，是映射表和数据区的总和==。
	- 有效位：判断cache内容是否有效。
	- 修改位（脏位）：用于回写法。
	- 替换控制位：用于组相连和全相连。
3. 地址划分
	cache：Cache块号(高位地址)+块内地址(低位地址)3位的Cache行号+2位的块内地址
	主存地址：
		地址位数：对地址空间取对数。
		主存块号：主存块号（高位地址）+块内地址（低位地址）

	对于任何一个主存地址,当块内占2b,行号占2b,则`x/4`相当于去掉了块内地址,得到的是主存块号,==然后再`(x/4)%4`,则得到了cache行号==.从而计算时不需要转为二进制数.
![](<Pasted image 20260825164928.png>)
若主存与Cache块大小相同，且主存容量是Cache数据区容量的32倍，则主存块数是Cache行数的32倍，因此主存块号比Cache行号多5位。而这==多的5位用于做标志位==。
### 映射方式
#### 全相联
1. 划分地址
![](<Pasted image 20260825165911.png>)
2. 比较器：由于映射到所有行，所以需要n个比较器。且==比较器位数等于tag位数==。
3. LRU位：LRU算法对每个Cache行设置一个计数器(也称LRU替换位)，用计数值来记录主存块的使用情况。通过硬件修改计数值，并根据计数值选择淘汰某个cache行中的主存块。==全相联时每个Cache行的计数器位数通常为log2(Cache行数);r路组相联时每个Cache行的计数器位数通常为log2(r)。==
4. 冲突概率最低，但实现成本最高。
![](<Pasted image 20260825170333.png>)
#### 直接映射
1. 划分地址
![](<Pasted image 20260826140310.png>)
2. 比较器个数:由于每次映射到唯一的cache行,所以==只需要一个比较器.==
![](<Pasted image 20260826140538.png>)
3. 不需要LRU位.
4. 实现简单,但冲突概率高.
#### 组相连
1. 地址划分
![](<Pasted image 20260826140731.png>)
2. 比较器个数:与该组中r路进行比较,所以需要设置r个比较器.
![](<Pasted image 20260826140836.png>)
3. LRU位与cache组大小有关.如图为四路组相联,所以每个cache行需要2位LRU计数值.
### 局部性原理
#### 指令
1. 对于循环结构,有时间局部性.
2. 对于顺序结构,有空间局部性.
#### 数据
1. 针对某个变量,在短时间内被访问多次,则存在时间局部性.
2. 针对数组
	存在空间局部性.
	当要判断是否有时间局部性时,要从数组元素出发(==在访问时,其是独立的==).若每个元素仅仅访问过一次,则不存在时间局部性.
![](<Pasted image 20260826141546.png>)

### 计算平均访存时间
1. 命中率p
2. 命中时间:==如果数据在cache中==，则称为数据命中(Hit)，将命中时的数据访问时间称为命中访问时间为Tc，该时间包括查找时间和cache访问时间两部分。
3. 缺失补偿时间:==如果数据不在cache中==，则称为数据缺失(Miss)，此时需要将缺失数据从主存调入cache中才能访问数据；数据缺失时的访问时间称为缺失补偿，缺失补偿包括数据查找时间、主存访问时间、cache访问时间，==访问主存的过程较为漫长，通常用主存访问时间Tm表示==。
4. 平均访问时间:
	同时启动:即同时访问cache和主存,`p*Tc+(1-p)*Tm`.
	先后启动:`p*Tc+(1-p)*(Tm+Tc)=Tc+(1-p)*Tm`.

### cache缺失处理时间计算
1. 存储器读事务
	传送地址和命令
	存储器准备数据(题目会给出存储周期T)
	传送数据(会给出总线时钟周期)
![](<Pasted image 20260826143326.png>)
2. 结合多体交叉存储器
	例如，Cache块大小为32B，主存采用8体交叉存储方式，每个体的存储字长为32位，存储周期为40ns，总线宽度为32b，总线时钟频率为200MHZ，支持突发传送方式。每次传送地址或32b数据均需要一个总线时钟周期。

	发生cache缺失时,由于总线为32b,所以采用轮流启动方式,要突发传送8B.所以主存准备数据要`40+7*5ns`,然后发送最后一个数据需要5ns,最初传送地址需要5ns,所以共需要85ns.
![](<Pasted image 20260826143840.png>)
当要计算CPU执行时间时,采用==总时间法:全部命中所需的基本执行时间+缺失额外开销==.
### cache一致性问题
记忆口诀为:非全.
1. 写命中
	全写法:适用于安全性要求高,一致性要求高.
	写回法:适用这种方法,要求==设置1bit的脏位==,当cache要被替换出去时,根据脏位来确定是否要写回主存.==适用于大量写操作,数据访问密集型程序.==
2. 写未命中
	写分配:在写入主存后,还要将写入过的主存块调入cache中.遵循了局部性原理.
	非写分配:没有遵循局部性原理.
![](<Pasted image 20260826144554.png>)
### 替换算法
发生在==全相联和组相连==中.
1. 随机分配
2. 先进先出:替换最早调入的cache行.
![](<Pasted image 20260826145416.png>)
3. 近期最少使用算法:依据局部性原理.即LRU算法.
![](<Pasted image 20260826145522.png>)
4. 最不经常使用算法:==根据频次==,将访问次数最少的cache行替换掉.
