## 1. 本质
从操作系统的角度出发，管理I/O操作的执行流程。
  
## 2. 结构/组成
### 设备分类
1. 字符设备：
	类似鼠标键盘等，以字符为单位，不可寻址。
2. 块设备：
	以数据块为单位，可以寻址。常见有磁盘、光盘等。
3. 虚拟设备：
	采用假脱机技术，使物理设备变为多个逻辑设备。
### 设备控制器
又称IO接口，区别于IO端口（IO接口中的寄存器）。
![IO接口](<Pasted image 20260521152419.png>)
  - 区别控制寄存器（保存对外设的控制信息）和控制线（用来传输控制信号和中断信号等）。
  - **IO控制逻辑**是大脑，==实现设备控制功能==。
	1. 将控制寄存器的信息译码为控制信号给外设
	2. 在数据缓冲寄存器和外设之间发送和接收数据
	3. 收集外设状态到状态寄存器中
- 编制方式
	1. 统一编制：外部设备（实际为IO接口中的各个寄存器）和内存统一编制。
		优点：共用IO指令，保护机制，提高了编程的灵活性。
		缺点：增加了译码的复杂度。同时减少了主存可用容量。
	2. 独立编制：x86处理器采用这种方式。需要专门的IO指令。
		优点：降低了译码复杂度，寻址速度更快。同时程序更加清晰，有助于理解和检查。
		缺点：降低了灵活性，同时需要专门的硬件保护机制。
### IO通道
在CPU和设备控制器之间增加了**通道（是一种硬件机制）**，目的是==建立独立的IO操作==。
![通道技术](<Pasted image 20260521153855.png>)
- 区别所学的==覆盖技术、交换技术、内存缓冲池技术、SPooling技术==。
- 是一种==特殊的处理机制==，没有自己的内存，IO通道指令类型单一。
- 独立于CPU，执行对应的IO通道程序，当完成后，会向CPU发出中断信号。

### IO控制方式：程序中断
当IO设备准备好后，会向CPU发出中断请求进行处理。
![程序中断](<Pasted image 20260521163626.png>)
示例过程：
![程序中断示例](<Pasted image 20260521163938.png>)
```
若当前CPU正在执行进程A的用户程序，其无法访问内核空间，因此需调用系统调用函数print()
去把它打印出来。用户程序的部分代码如下。
print(buffer, strlen(buffer));   此时进程处于用户态。
对于系统调用函数printO）（内核函数），它的部分代码如下。
copy_from_user(buffer, p, count);//将用户空间数据复制到内核缓冲区
enable_interrupts( );
while(*printer_status_reg!=READY)//轮询状态端口，直到设备返回READY状态i= 0;
*printer_data_reg = p[i];
scheduler( );//程序调度
```
这段代码的说明如下：也就是==**设备驱动程序**==。
①把buffer缓冲区中的字符串复制到p指向的内核缓冲区中，通过P[i]访问不同字符。==此时进程已经由用户态变为内核态==。==变为特殊的运行态==。
②打开中断，这样，CPU就能够处理中断。
③轮询状态端口，判断打印机的当前状态是否空闲。如果不空闲，就一直循环等待。否则，就把循环变量i初始化为0，并把需要打印的P[0]放入数据端口中。注意，这里仅仅是把P[0]放入到数据寄存器中，然后就不管了。
④接着，调用进程调度程序，切换到另一个进程B去执行，而自己则会被阻塞起来，并且挂到相应的阻塞队列中。
后续的字符处理则在==**中断处理程序**==当中，==**该中断处理程序依附于被中断的进程**==，而该进程已经被阻塞，当字符处理完后，由阻塞态变为就绪态。
```
if(i >= count-1){
unblock_userQ;
//所有字符打印完毕
}
}else{
i=i+ 1;
*printer_data_reg = p[i];
}
acknowldege_interruptO;//向中断控制器发出确认
return_from_interruptO;//中断返回指令，但是否真正返回，取决于调度程序。
```

### IO 控制方式：DMA
用于对数据块的传输，外设可以和内存直接进行数据传输，==信息传送不经过CPU==。
![DMA结构图](<Pasted image 20260521170530.png>)
- 注意DMA接口与主存之间的==传送单位为字==，而外设与DMA接口之间的==传送单位为字节或位==。
- 当外设准备好一个字后，会向DMA发送==DMA请求==；当传输完毕后，DMAC会向CPU发出==中断请求==，报告DMA结束。
![DMA执行流程](<Pasted image 20260521172725.png>)
- 传送方式：
	1. 停止CPU访存：控制较简单
	![停止cpu访存](<Pasted image 20260521173634.png>)
	2. 交替访存：在每个存储周期内，二者都可以访存，但是增加了存储周期
	![](<Pasted image 20260521173724.png>)
	3. 周期挪用：会在每个机器周期结束时，进行传送
	![](<Pasted image 20260521173755.png>)
### IO管理的软件层级结构
由以上的案例分析可知，操作系统下的软件层级结构：
```
用户软件
设备独立性软件
设备驱动程序
中断处理程序
```
案例分析
1. 从**用户软件**开始
```
用户程序
void main() {
int x,
scanf("%d"，&x);//调用库函数
}

库函数
int scanf(char *format[, argument, ]) {
//…其他逻辑
read(……);//调用read系统调用
}
```
当执行main函数和scanf函数时，进程处于==用户态==；当执行到read系统调用时，发生了进程切换，变为==内核态==。

2. 到**设备独立性软件**
```
系统调用
int sys_read(……) {
int devID=get_devID(……);//获取设备号
chrdev_sw[devID].read(…);//调用字符类设备接口函数
}
```
为了找到对应的设备驱动程序，会为字符类设备设置一张==字符设备开关表==：
![](<IMG_20260521_210601.jpg>)
3. **设备驱动程序**：与硬件直接相关，是设备的生产商提供。前面的程序查询方式实例可以看作是简单的驱动程序。运行时，==位于操作系统的内核空间==中，来指挥具体的外设工作：
		将抽象要求变为具体要求
		校验服务请求
		检查设备状态
		向外设传送必要的参数
		启动IO设备
![](<Pasted image 20260521211348.png>)
整个驱动程序中包含了中断处理函数：==用于设备完成IO时，向CPU发中断后被调用==。一般善后处理是将被阻塞IO进程变为就绪态。

## 5. 易错点
- 内核态不以独立进程形式存在
- 中断处理程序是操作系统内核中的一段程序代码，**不是独立运行的进程**，因此不建立 PCB。中断发生时，CPU保存当前进程现场后转去执行中断处理程序，中断结束后再恢复原进程执行。
	1. ==中断例程依附于被中断的进程上下文。==
进程A运行时发生中断：
```
A 的内核栈
A 的 PCB
A 的地址空间   这些都还在。对于保护现场，这些信息保存到内核栈或者PCB中。
```

2. 中断处理==只是临时借用CPU，执行内核代码==。
3. 中断例程结束时，会==执行中断返回指令==，但是不一定是被中断的进程（取决于**调度程序**）。
