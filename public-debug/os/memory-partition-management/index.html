3.2 内存分区管理

连续分配、动态分区分配、动态重定位和内存回收的核心知识整理。

分区管理

重点

1. 本质

程序在装入内存后的具体空间分配，本章节为连续分配，也叫分区管理。

2. 结构/组成

单一连续分配

适用于单道程序环境中。

固定分区分配

使用 分区表 来管理空闲分区。

分为分区大小均等和分区大小不等两类。容易产生 内部碎片，且该方法不灵活。

动态分区分配

使用 空闲分区表 和 空闲分区链 两种方式进行管理。正常情况下，链表结点会占用用户空间。

关键在于外部碎片和大空闲区的冲突。

顺序分配：

  1. 首次适应算法：一直在一处薅羊毛，容易造成很小、难以利用的 外部碎片。
  2. 循环适应算法：容易使大空闲区缺乏。
  3. 最佳适应算法：产生的外部碎片最多。注意在内存分配和回收时，必须对空闲分区进行排序。
  4. 最坏适应算法：使大空闲分区缺乏。注意在内存分配和回收时，必须对空闲分区进行排序。
算法 思想 优点 缺点
首次适应 从头找第一个 快 前部碎片
循环首次 接着上次位置找 更均匀 大块减少
最佳适应 找最小满足块 利用率高 小碎片多
最坏适应 从最大块分配 避免小碎片 大块被拆

索引分配：

对空闲分区根据大小进行分类，类似图的邻接表。

  1. 快速适应：不会对分区进行分割。
  2. 伙伴匹配：分区大小为 2 的 K 次幂，内存分配和回收涉及到分区的分割与合并。
  3. 哈希算法：索引结构与快速适应一样，只不过使用哈希算法，来更快找到合适的分区。

动态重定位分区分配

使用了基地址寄存器，从而实现 紧凑 技术，不过该技术系统开销较大。

内存回收

根据具体情况，要么合并，要么不合并。
